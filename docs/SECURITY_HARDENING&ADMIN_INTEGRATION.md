# ТЕХНИЧЕСКАЯ СПЕЦИФИКАЦИЯ: SECURITY HARDENING & ADMIN INTEGRATION (v1.3.0)

Настоящий документ регламентирует внедрение комплексного профиля безопасности (Hardening Suite) на сервере и интеграцию модуля мониторинга/управления защитой в веб-панель управления ботом.

---

## 1. ЦЕЛИ И ЗАДАЧИ

1. **Защита сетевого периметра:** перевод хоста в режим скрытности (Stealth Mode) от сетевых сканеров (Shodan, Censys) и ботнетов без нарушения MTU Discovery.
2. **Изоляция служебных сокетов:** блокировка внешнего доступа к техническим портам `2096` (подписки 3X-UI), `1488` (локальный бэкенд Flask), `8085` (внутренний fallback заглушки Nginx) и стандартному `22` (SSH).
3. **Сохранение кастомного управления:** автоматическая адаптация правил фаервола и Fail2ban под нестандартный рабочий порт SSH.
4. **Централизация в веб-интерфейсе:** добавление раздела «Безопасность» в панель администрирования бота с возможностью просмотра статуса и запуска харденинга в один клик.

---

## 2. АРХИТЕКТУРА И ЭТАПЫ РЕАЛИЗАЦИИ

### ЭТАП 1: Разработка скрипта харденинга
**Файл:** `src/scripts/server_security_harden.sh`

#### Требования к скрипту:
1. **Динамическое определение SSH-порта:**
   - Чтение слушающего сокета через `ss -tulpn | grep -E 'sshd|ssh'` либо парсинг директивы `Port` в `/etc/ssh/sshd_config`.
   - Использование определенного порта для правил UFW и Fail2ban.
2. **Тюнинг ядра и сети (`/etc/sysctl.d/99-neovpn-security.conf`):**
   - Блокировка ICMP echo: `net.ipv4.icmp_echo_ignore_all = 1` (запрет прямого пинга при сохранении валидации MTU).
   - Защита от SYN Flood: `net.ipv4.tcp_syncookies = 1`, `net.ipv4.tcp_max_syn_backlog = 4096`.
   - Защита от спуфинга и аномальных пакетов: `rp_filter = 1`, логирование `log_martians = 1`.
3. **Конфигурация фаервола UFW:**
   - Политика по умолчанию: `incoming deny`, `outgoing allow`.
   - Белый список (открыты): `$SSH_PORT/tcp`, `80/tcp`, `443/tcp`, `443/udp`, `8443/tcp`, `42357/tcp`.
   - Черный список (блокированы наружу): `22/tcp`, `2096`, `1488`, `8085`.
4. **Автоматические security-патчи:**
   - Конфигурация `unattended-upgrades` строго для репозиториев `*-security` с ежедневной проверкой.
5. **Контроль Fail2ban:**
   - Проверка статуса активного сервиса (без перезаписи рабочих джейлов панели 3X-UI).
6. **Права доступа (File Hardening):**
   - Установка прав `0600` на файлы SQLite (`*.db`) и закрытые SSH-ключи в `data/ssh_keys/`.
   - Установка прав `0700` на директории хранения ключей и `/etc/letsencrypt`.
7. **Генерация артефактов аудита:**
   - Экспорт структурированного JSON-файла для панели: `data/security_audit.json`.
   - Формирование веб-страницы отчета: `/var/www/neo-vpn-landing/audit.html`.

### ЭТАП 2: Бэкенд-контроллер панели управления
**Файл:** `src/shop_bot/modules/enhanced_admin_routes.py` (или соответствующий роут админки)

#### Реализуемые эндпоинты:
1. **`GET /admin/security`**:
   - Читает файл `data/security_audit.json`.
   - Рендерит шаблон `templates/admin/security.html`.
2. **`POST /admin/api/security/run-hardening`**:
   - Запускает `bash src/scripts/server_security_harden.sh` через `subprocess.run`.
   - Задает таймаут выполнения: 120 секунд.
   - Возвращает JSON: `{ "success": true/false, "output": "stdout/stderr log" }`.

---

### ЭТАП 3: Фронтенд (UI/UX)
**Файл:** `src/shop_bot/resources/templates/admin/security.html` (или путь к текущим шаблонам)

#### Компоненты интерфейса:
1. **Информационные карточки статуса:**
   - **SSH Shield:** отображение рабочего кастомного порта и статус блокировки порта 22.
   - **ICMP Stealth:** индикатор скрытности (зеленый/красный).
   - **Fail2ban & Updates:** статус демонов защиты и автообновлений безопасности.
   - **Служебные порты:** индикаторы изоляции портов 2096, 1488, 8085.
2. **Панель управления действиями:**
   - Кнопка **«Применить профиль Hardening»** с подтверждением действия.
   - Модальное окно или терминальный блок с выводом логов выполнения в реальном времени.
